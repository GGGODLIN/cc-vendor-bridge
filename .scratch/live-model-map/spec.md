# 即時 CC 模型映射表

## Problem Statement

使用者已取得一份 CC 模型映射盤點，但固定文字會隨版本表、啟動器設定與免費池候選變更而過期。使用者希望直接從終端機查看當下映射，並在啟動相關入口時看到整張表，而不是再次要求 agent 盤點。

## Solution

沿用 `ccp-list` 作為手動查詢入口。相關非直連啟動器在互動啟動時顯示同一張完整映射表，把本次啟動入口置頂並標示「▶ 本次啟動」。置頂列使用本次套用的設定，其他列使用各入口當下預設；表尾顯示 `free` 與 `free-smart` 的當下候選順序。腳本模式不自動插入表格。

## Implementation Decisions

- 手動入口沿用 `ccp-list`；無參數顯示全表，指定一個受支援入口時仍顯示全表，但將指定入口置頂。互動啟動與手動查詢共用解析與渲染邏輯，不新增另一張手動維護的模型版本或免費池名單。[user: "好，就照這版做"]
- 表格包含入口、主 session、Fable、Opus、Sonnet、Haiku；明設的預設 subagent model 另行說明，不宣稱該欄位覆蓋所有明示 agent model。[evidence: 本次盤點讀到部分啟動器另外設定 CLAUDE_CODE_SUBAGENT_MODEL]
- 自動顯示涵蓋 GPT、GPT／免費池混用、全免費池、Gemini、一般 relay、Bruce、DeepSeek 相容代理，以及保留原生 Claude 主力的 Luna／免費池分流入口。原廠直連、管理 helper 與不新增模型槽位的純啟動器不列入。[evidence: 本次 CC 模型盤點中的入口表與已安裝分流入口]
- 本次啟動的列標示「▶ 本次啟動」，其他列保持固定順序；手動指定入口使用「▶ 查詢入口」，避免把預覽標成已啟動。[user: "能直接顯示整張表嗎？然後當下啟動的放最上面之類的"]
- GPT 型號每次重新讀取共用版本來源，既有 shell 內的舊快取不可讓新表或新啟動仍使用舊型號。變更只更新讀取時機，不改版本表的內容。[user: "OK，這張目前版本表挺不錯了，有辦法做成指令嗎？或是相關指令啟動的時候順便顯示出來？而且要跟上當下狀況這樣"]
- 槽位資料必須與啟動器使用同一來源；若需要抽取共用設定，保留原本各入口的覆寫、強制固定、Fast header 與預設 subagent 行為，不趁本次改動重新選模型。[inferred]
- 免費池每次從現行 relay 設定產生，過濾停用項後依 priority 排序；顯示候選名稱與可解析的模型終點。下游名稱無法解析時保留設定中的名稱並標「終點未解析」，不猜模型。[user: "好，就照這版做"]
- 表格描述「設定映射」，不把目錄存在、服務在聽或設定候選視為推理成功。本功能不送推理請求，不新增健康輪詢、quota 查詢或額度監測。[inferred]
- 自動顯示只適用互動啟動。print、批次輸出與非互動輸入不自動印表；明示執行 `ccp-list` 時可輸出表格供人工閱讀。避免在模型服務／MCP 子命令路徑插入表格。[user: "好，就照這版做"]
- 表格讀取或渲染失敗時，自動啟動路徑只提示錯誤並保留原啟動行為；手動查詢回報錯誤。模型設定不可因顯示失敗而改變。[inferred]
- 輸出只含入口、模型、非敏感路由名稱與讀取狀態；不顯示 key、token、帳號憑證或完整敏感 header。[inferred]

## Testing Decisions

驗收界面為使用者已確認的終端輸出與啟動器傳給 CC 的模型設定。沿用現有 shell 測試的假啟動器與隔離設定檔做法，不啟動真實模型 session。

- 手動執行後，看到整張非直連映射表與兩條免費池候選順序。
- 在隔離終端中啟動每個受支援入口後，本次入口列置頂且只標記一次；其他列仍是乾淨預設。
- 改動隔離版本表後，不重新 source 啟動器也能在下一次查詢／啟動看到新型號。
- 改動隔離 relay 設定的 priority／disabled 後，下一次表格反映新順序與移除停用候選。
- 傳入模型環境覆寫及明示模型參數後，置頂列與假 CC 捕捉到的設定相符；原參數保持不變。
- 非互動、`-p`／`--print` 與機器可讀輸出模式沒有自動表格，假 CC 的 stdout 原樣保留。
- 缺檔、無法解析與缺依賴案例清楚標示未知；自動顯示失敗不阻止假 CC 啟動。
- 配置假的 credential canary，確認表格與錯誤輸出均沒有洩漏。
- 執行相關既有啟動器測試，辨識本次變更與動工前已存在的失敗；不為了把測試變綠修改本次無關的模型選擇。

既有測試先例是免費池啟動器測試的隔離版本／relay／帳號 fixture，以及 GPT routing 測試捕捉最終槽位值的做法。

## Out of Scope

- 更換實際模型、升級版本、調整免費池候選／priority 或修復上游服務。
- 原廠直連入口、Codex CLI、網頁版 GPT、MCP 與 hook 消費者的完整盤點。
- agent 派工異常的修復。
- 啟動後持續追蹤 `/model` 切換；標記描述本次啟動，不宣稱是即時 session 監視器。
- 每次啟動額外送模型探針、quota 查詢、健康輪詢或推理測試。
- 終端機 UI 的長駐面板、分頁器、互動選單或新設定管理系統。
- 覆蓋或納入動工前已存在的未提交改動。
